# SigNoz root-user provisioning

Checked on 2026-11-12 against the pinned **SigNoz v0.147.0** image.

- Root provisioning runs at startup when `SIGNOZ_USER_ROOT_ENABLED=true`. Configure `SIGNOZ_USER_ROOT_EMAIL`, `SIGNOZ_USER_ROOT_PASSWORD`, and `SIGNOZ_USER_ROOT_ORG_NAME`. The feature is available from v0.112.0; no image upgrade is needed. [Official configuration guide](https://signoz.io/docs/manage/administrator-guide/configuration/root-user/), [v0.147.0 configuration](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/config.go).
- **`admin` is rejected.** The pinned release validates root passwords before startup: at least 12 characters, including uppercase, lowercase, a digit, and a supported symbol. `Admin123456!` satisfies those rules. The password policy is enforced in code, not an optional Compose setting. [Root configuration validation](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/config.go#L76-L85), [password validation](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/types/factor_password.go#L162-L199).
- The organization name must match the existing SQLite organization. Without an explicit organization ID, a missing name match creates a new organization and first root user. For this installation, the existing organization had a NULL name; assigning `default` to that one organization preserves its ID and data while allowing name-based provisioning. Do not rename unrelated organizations or clear volumes. [Official existing-install instructions](https://signoz.io/docs/manage/administrator-guide/configuration/root-user/#existing-installs), [organization resolution and creation](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/impluser/service.go#L91-L115).
- Within the selected organization, provisioning creates a root user, promotes a matching ordinary user, or updates the existing root user's configured email/password. Restarting applies credential changes; it is not a fresh-install-only feature. Root users receive the admin role. [Startup reconciliation](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/impluser/service.go#L117-L235).
- Root users cannot be edited, deleted, or have passwords changed/reset through ordinary user-management operations. Change the environment configuration and recreate the SigNoz container instead. With Compose, run `docker compose up -d signoz`; `docker compose restart` alone does not load changed environment values. [Root-operation restrictions](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/impluser/setter.go#L164-L215), [password-change restriction](https://github.com/SigNoz/signoz/blob/v0.147.0/pkg/modules/user/impluser/setter.go#L481-L493), [Compose environment changes](https://docs.docker.com/reference/cli/docker/compose/restart/).
